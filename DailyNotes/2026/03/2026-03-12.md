## Study Note
### [System Design] Basic - Message Queue
- What does this solve? When to use?
  - Async work
  - Handle high traffic
  - Decoupling the systems
  - Reliability - MQ holds message

- What is a message queue?
  - Producer -> MQ -> Consumer (Process whatever needs to be done)
  - Types of MQ: Consumers send an ACK to MQ
    - 3 edge cases
  - Delivery Guarantees
    - At-least-once: most common, almost always the right answer
    - At-most-once: analytics events are acceptable
    - exactly-once: only a small use case of Kafka that supports this

- Deep Dive
  - Handle increasing throughput
    - Split MQ into multiple partitions: Amount of partitions <= Amount of consumers
  - Producers produce more messages than consumers can process -> MQ can run out of memory
    - Back pressure: reject incoming message from producers if reach some limit
  - Message is failed to process due to a malformed message that crashes the consumer all the time
    - Configure a max retry attempts then put in DLQ
  - MQ fails

- Common Technologies
  - Kafka: most popular for both the interviewing and industry
  - SQS
  - RabbitMQ

### Codeforces
- [A. Football](https://codeforces.com/problemset/problem/96/A)
```python3
players = input()

counts = 1
for idx in range(1, len(players)):
  prev = players[idx-1]
  cur = players[idx]

  if prev != cur:
    counts = 0
  counts += 1
  if counts == 7:
    print("YES")
    exit()
if counts == 7:
  print("YES")
else:
  print("NO")
```
